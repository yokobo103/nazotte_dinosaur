# なぞりん 対応案 — Grokの提案をどう受けるか

2026-08-28 / 対象: 試作v3（ひらがな・カタカナ178字、筆跡が残る、お手本との距離で採点、報酬は「ずかん」）

## 結論

Grokの提案は「既存の人気アプリと市場で戦うなら何を載せるか」の網羅リスト。
このアプリはまだラボの試作で、Google Play の1本目は別にある（ころがしタイムアタック）。
だから**網羅ではなく、すでに他と違う1点を尖らせる**方向で受ける。

- **採る3つ**: きょうの れんしゅう（苦手特化）／読み上げの声／オフライン
- **採らない5つ**: ミニゲーム融合・アバター育成・多要素セット・ストリーク・AR/ウィジェット
- **その前に**: 実機で触ってもらう。3つとも「触ってから」の方が精度が上がる

---

## 採る① きょうの れんしゅう（Grok「SRS＋苦手重点練習」）

### なぜ

**いま最大の穴**。一度なぞったら ずかんが開いて終わりで、忘れる仕組みが入っていない。
46字を一周したらやることが無くなる。飽き対策の本命はここで、ミニゲームの追加ではない。

そして半分はもう出来ている。v3で字ごとに `best`（いちばん良かった点数）を持たせたので、
**苦手の判定材料はすでに手元にある**。

### 「にがて」とは呼ばない

Grokの言葉は「苦手重点練習」だが、4歳に「にがてのじ」というラベルを見せるのは筋が悪い。
やりなおしの理由を責めない言い方にしたのと同じ理由で、**中身は苦手特化、見せ方は
「きょうの れんしゅう」**にする。子どもからは「今日の5もん」に見えて、
中で苦手と忘れかけを選んでいる。

### どう作る

**データ**（`app/js/main.js` の `stamps`）

```js
// いま:   { "あ": { n: 3, best: 88 } }
// これから: { "あ": { n: 3, best: 88, last: 20260828, recent: [72, 81, 88] } }
```

`last` = 最後にやった日（数値の YYYYMMDD）、`recent` = 直近3回の点数。
v2/v3の保存は `loadStamps()` がすでに引っ越しを持っているので、欠けたら埋める形で足す。

**選び方**（1日5字）

| 枠 | 中身 | 数 |
|---|---|---|
| わすれかけ | 期日が来た字。★3=7日後 / ★2=3日後 / ★1=翌日 | 最大3 |
| にがて | 直近平均が低い順（未挑戦は除く） | 最大2 |
| あたらしい字 | まだ ずかんが開いていない字を、五十音順に | 残り |

未挑戦の字を「苦手」に混ぜない。**まだ、と にがて は別物**。

**画面**

- 表のヘッダに「きょうの れんしゅう ▶」の帯を1本。押すと5字を続けてなぞる
- 進みぐあいは「●●○○○」。終わると「きょうの れんしゅう おわり！」＋ずかんへ
- 苦手だった字の★が上がったら「『ぬ』が ★★★になった！」を出す（更新の実感）
- 全部やり終えた日は「きょうは おわり。また あした」——**やらせすぎない**

**工数感**: 小。判定エンジンには一切触らない。`main.js` に選び方と1画面を足すだけ。

### 決めること
- 1日の数は5字でいいか（3字だと物足りない、7字だと幼児には長い）
- 名前は「きょうの れんしゅう」でいいか

## 採る② 読み上げの声（Grok「音声がきれい」）

### なぜ

いまはブラウザの `SpeechSynthesis`（機械音声）。端末によって声も読み方も変わり、
無い環境では黙る。幼児向けで「声がきれい」は効くという指摘は妥当。

### どう作る

ラボに音声を焼く装置がある（`video-lecture-maker` のTTS）ので、**178字ぶんを事前に焼いて置く**。

- 読み上げ文は `app/js/words.js` の `readingOf()` がすでに全字ぶん持っている
  （例:「あ、ありの あ」）。台本を書く作業は要らない
- 1字1〜2秒 × 178。mp3 mono 24kbps なら合計 **1MB弱**。オフライン化とも両立する
- ファイルが無い / 読めない環境では、いまの `SpeechSynthesis` に落ちる作りにする
- ついでに「かんぺき！」「ずかんに はいった！」などの決まり文句も焼く

**工数感**: 中。焼くのは自動、埋め込みは `say()` の差し替えだけ。

### 決めること
- **どんな声にするか**。よこぼの声 / 女性 / 子ども寄り。ここは決裁事項

## 採る③ オフライン対応（Grok「親視点の安心」）

### なぜ

子どもに渡すタブレットが電波なし、は普通にある。前回こちらから挙げていた案件で、
Grokも「親が安心して渡せる」の条件に挙げていて裏が取れた。

### どう作る

Service Worker を1枚。全部で60KB（＋アイコン、＋②の音声1MB）しかないので全部プリキャッシュ。

- キャッシュ名にバージョンを埋め、`skipWaiting` + `clients.claim` で次の起動から新版
- GitHub Pages 前提なので `scope` とパスは相対で書く
- 検査に「2回目の読み込みがネットワーク遮断でも通るか」を1項目足す

**工数感**: 小。ただし更新が効かなくなる事故が一番怖いので、検査を必ず付ける。

## 採らない

| 提案 | 採らない理由 |
|---|---|
| ミニゲーム融合（もぐらたたき・しりとり・間違い探し） | 背骨がぶれる。v3で「自分の筆跡が残る」を主役にしたばかりで、ミニゲームを足すと**書いている時間が減る**。飽き対策は採る①で解く |
| アバター育成・レベルアップ | 報酬の背骨は「ずかん」で決まっている。同じ軸に2つ置くと、どちらも薄くなる |
| 多要素セット（数字・形・仲間分け） | 「書く対象を増やす」（数字・アルファベット）はカタカナと同じ装置でほぼタダなので**あとで安く足せる**。だが「形」「仲間分け」は別のアプリ。横に広げても深くならない |
| ストリーク・デイリー目標 | 対象は子ども。連続日数を気にするのは親であって幼児ではない。外国人学習者向けに舵を切るなら再検討 |
| AR宝探し・カメラ連携 / ウィジェット | ARは学習の話でなく新鮮味の話（ラボには既にARねんどがある）。ウィジェットはWebでは作れずネイティブが要る |

（数字・アルファベットだけは「保留」に近い。KanjiVGと同じ要領で足せるので、
①②③のあと、実機で「もっとやりたい」が出たら足す）

## 順番

```
0. 実機で触ってもらう（GitHub Pages に上げる）   ← ○×待ち
1. ① きょうの れんしゅう                        小
2. ③ オフライン                                 小
3. ② 読み上げの声                               中（声の決裁が要る）
4. （保留）数字・アルファベット
```

**0を先にやる理由**: ①②③は全部「どこが物足りないか」を触ってから決めた方が精度が上がる。
実機で触っていない状態でいくつも積むと、外した分がまるごと無駄になる。

## よこぼに決めてほしいこと

1. **GitHub Pages に上げていいか**（公開になる）
2. きょうの れんしゅうは **1日5字** でいいか
3. 読み上げの **声は誰か**（②に着手するときでよい）
