# よこぼの なぞって！きょうりゅうはっくつたい

指でかなをなぞると恐竜の骨が発掘できる、子ども向けの練習アプリ。
書いた線はそのまま残り、お手本との似ぐあいで点がつく。
ビルド不要の素のHTML/CSS/JS。スマホ・タブレット縦持ち前提。

公開版: <https://yokobo103.github.io/nazotte_dinosaur/>

トリケラトプス完成状態: <https://yokobo103.github.io/nazotte_dinosaur/triceratops-complete.html>

## うごかす

```bash
python -m http.server 8143 --directory app
```

ブラウザで <http://localhost:8143> を開く。

## 遠隔テスト

Node.js 24 と Python 3 を用意して、依存関係を入れる。

```bash
npm ci
```

別のターミナルで `npm run serve` を起動してから、検査を実行する。

```bash
npm test
npm run test:mobile
```

GitHubへpushすると、同じデスクトップ／モバイル検査がGitHub Actionsでも自動実行される。

## できること

- **ひらがな / カタカナ** を切り替えて練習する（ひらがな81字・カタカナ82字）
- **書き順どおりに1画ずつなぞる**。指が通った道がそのまま線として残る
- 1画おわるたびに ★と「いいね！／じょうず！／かんぺき！」、字がそろうと紙ふぶき＋読み上げ
- **おてほん**ボタンで書き順を再生。3.5秒とまると書きはじめの丸が光る
- 効果音はWebAudioの合成。音源ファイルは0バイト。最初のタップでAudioContextを起こす
- 読み上げはブラウザのSpeechSynthesis（ja-JP）。無い環境では黙るだけ

## 3つのボタン（2026-09-02 に組みかえ）

ホームは **たんけんに でる（大） / はっくつずかん（小） / はっくつれんしゅう（小）** の3つ。
50音表はホームから出して、**はっくつれんしゅう**という専用ページへ移した。

| | だれが | 何を | 終わり方 | ホネ |
|---|---|---|---|---|
| **たんけんに でる** | 子どもが1人でも | 自動でえらばれた5もじ | 3回×5もじ＝15回 | **1個** |
| **はっくつれんしゅう** | 親と一緒のときだけ | 自分でえらんだ1もじ | 3回 | **なし** |

**なぜ分けたか。**もとは50音表がホームにあり、押すと「その字から表を順に流す」練習が始まった。
実測すると `ぬ→ね→の→は…` と46字を**無限に回り**、終わりも報酬も無く、
「ぬが苦手だから繰り返したい」には一度も応えていなかった。所長の整理は
「行単位で苦手な子はいない」「1人ではやらない、親と一緒のときだけ」。
それなら**専用ページ**で、**1もじ3回で終わり**。

**ホネを出さない理由は世界観だけではない。**報酬の物差しは「どの字か」ではなく
**15回なぞったら1個**。3回で1個にすると5倍になり、ミッションを回す理由が消える。

### れんしゅうの単位（セット）

**1文字を3回書いて、5文字ぶんで1セット。**セットを1つ終えると **ホネが1個**。

- 出す字は自動でえらぶ：**まだ書いていない字 → ★の少ない字 → のこりをランダム**
- **ミッションは きほん(清音)だけ**。だくおん(50字)・ちいさいじ(21字)は
  はっくつれんしゅう専用にした＝ホームに残るつまみが「ひらがな／カタカナ」1つで済む
- 1文字書けると**ひとりでに次へ進む**（子どもに「つぎ」を押させ続けない）
- れんしゅう中は **「つぎ」を隠す**。出しておくと書かずに飛ばしてホネがもらえてしまう

つまみは `app/js/main.js` 先頭の `REPS`（既定3）と `SET`（既定5）。

### せってい（おうちのひと向け）

⚙ を押すと開く。中身は **よこぼのAIラボの紹介＋実験室へのリンク / 素材のクレジット /
この端末の記録＋さいしょから やりなおす**。

**外へ出るリンクを子どもの主導線に置かない。**ホーム画面から起動したPWAで子どもが
外部リンクを踏むと、ブラウザが開いて**アプリに戻れなくなる**。読むのは親なので、
親しか行かない場所に置く。

**この画面だけ漢字で書いている。**ほかは全部ひらがななので、**見た目だけで
「ここは大人のページ」と伝わる**（子どもが開いても読めないので、そのまま閉じる）。

ラボへの入口はもう1か所、**しょうじょう（30こ達成）**の下にもある。
賞状の絵には「YOKOBO AI LAB」の看板がもともと描かれていて、字と絵で二重になる。

### かなの切りかえは、あえて子どもの手の届くところに

ひらがな／カタカナ は **「たんけんに でる！」のすぐ下**に置いた。設定(⚙)の奥ではない。
所長の指定は「**本人の好奇心でかえる余地を残したい**」。
⚙ は「さいしょから やりなおす」だけなので、ラベルもそう書いてある
（モックの「せってい」にすると、全部消すボタンの名前として嘘になる）。

### はっくつれんしゅう

**字を押す → えらんだ印がつく → 下の大きいボタンで始める**の2段。
親と相談してから始める場所なので、誤タップで走り出さないようにしている。
3回書くと「「ぬ」を 3かい なぞれた！」と自分の筆跡3枚が出て、表へ戻る。
表の下に**さいきん れんしゅうした もじ**（直近3字）が残る。

## 体験の流れ

**はっくつベース → 5文字をなぞる → 自分で書いた5文字 → 骨を発掘 → はっくつずかん**

の順で進む。なぞり画面は白い文字ボードを主役にし、発掘感はボード外の「はっくつエリア」表示と
5文字ぶんの骨進捗に限定している。筆跡は泥などの効果を使わず、ターコイズ1色の滑らかな線で描く。

図鑑で5つの骨がそろった恐竜は、専用の詳細ページが解禁されます。詳細ページでは
「ほねの すがた」と「いきていた すがた」を切り替えられます。未完成の恐竜は詳細へ
移動できず、姿・シルエット・復元画を表示しません。復元画や食性・大きさ・年代・地域は
`app/js/bones.js` の `detail` へ恐竜ごとに追加できます。ティラノサウルスを含む6体には復元画・説明・基本情報を
登録済みで、数値と年代はロンドン自然史博物館の Dino Directory を参照しています。
完成カードでも、全身骨格の下に集めた5つのパーツを小さく残し、収集の達成を見返せるようにしている。
ホームは発掘ミッションだけ。五十音表は「はっくつれんしゅう」ページへ移した。

セット終了時は各文字の3回目に成功した筆跡をカードで並べる。筆跡はCanvas画像ではなく
109座標系のストローク点列として `nazorin.handwriting.v1` に保存するため、将来の図鑑表示・
昔の字との比較・練習記録に再利用できる。

かなの図鑑（🐜あり などの絵を集めるもの）は**畳んだ**。集めるものはホネに一本化。
例のことばは、なぞり画面の上に出るヒントとして残っている。

## ホネ1つの きろく（マスを押すと出る）

ずかんのマスを押すと、**そのホネを掘り出した日と、そのとき書いた文字**が下から出る。
筆跡が残っていれば、**その子が書いた線そのもの**を並べる。

**5さいがマスを押していた（反応なし）**のがきっかけ。白いカードに骨の絵が入っていて
押せそうに見えるのに、何も起きなかった。
**押せそうに見えるものが押せないのは、いちばん伝わらない壊れ方。**
まだ取れていないマスも押せて、「もじを なぞって さがそう！」と返す。

記録は `dig.log["恐竜id:部位"] = { day, chars, sid }`。**1本79バイト・30本で2.3KB。画像は増えない。**
筆跡そのものは `handwriting.sessions` を `sid` で引く（あちらは古いものから捨てられるが、
日付と文字はこちらに残るので、記録が消えることはない）。

ずかんの並びは **そろった → 掘りかけ → 手つかず**。手つかずが上に来ると、進んでいるものが埋もれる。

## キャラクター（2026-09-01）

原画は `work/chars/`（Git外）。`node tools/make_chars.mjs` が配信用に焼いて
`app/assets/chars/` に置く。**焼き直しの手順は1つだけ** — 原画を差しかえて回す。

| 出るところ | 絵 | なぜそこか |
|---|---|---|
| 開いた直後 1.6秒 | キービジュアル | 押させない。押して閉じる形にすると、毎日やる練習に1タップ増える |
| ホームの見出し | ロゴ | 白地は外周から塗りつぶして透過にしている（絵の中の白は残る） |
| ホームのミッション | Dr.よこぼ（手をふる） | 96px以上でしか使わない。毛の描き込みが多く、小さいと潰れる |
| なぞる画面の板の下 | ニャビット（6表情） | **まだ字が読めない子に、★とやりなおしの理由を顔で伝える** |
| ごほうび画面 | Dr.よこぼ／ニャビット | セット完了は Dr.よこぼ、ホネ発見はニャビット |
| ずかん コンプリート | しょうじょう | 30こ そろった日を絵の空欄に書きこむ |
| ホーム画面のアイコン | ニャビットの顔 | `tools/make_icons.mjs` が `ny_idle.webp` を埋めて焼く |
| ミッションカード | Dr.よこぼ（つるはし） | 掘っている姿。ホームの主役が「掘る」ことなので |
| はっくつれんしゅう の見出し | ロゴ画像 | 横長なので**ページの見出し専用**。ホームのボタンは文字＋アイコン |
| はっくつずかん の見出し | ロゴ画像 | 同上 |

どのコマを使うかは、**実際の大きさに並べて見てから**決めた。
ニャビットは40pxでも表情が読めるが、Dr.よこぼは56pxで顔がつぶれる。だから役割が違う。

### 切り抜き（2026-09-01 に作り直した）

表情シートは**透過PNG（5列2行×2枚＝1キャラ20コマ）**。背景はもともと透明なので、
**アルファをそのまま使って形どおりに抜く**（丸く抜かない）。切り出しは Node だけで動く
（`tools/png.mjs` が PNG を読み書きし、`tools/sheet.mjs` が塊を拾う）。
WebPにするところだけヘッドレスChromeを使う。

つまずいた2つ:

- **マス目でぶつ切りにしない。**となりのコマの飾り（💢・✨）が境目をまたぐと切れる。
  実際に1コマ、となりの破片が写り込んだ。**つながっている塊ごとに、いちばん近いコマへ
  割りあてる**（4近傍の連結成分）。
- **外接矩形に合わせて縮めない。**飾りの分だけ枠が広がるので、飾りの多いコマほど顔が
  小さくなる（実測：顔の高さは 200〜210px でそろっているのに、幅は 213〜290px）。
  **倍率は全コマ共通、位置は顔の重心でそろえる**。重心にしたのは、20コマを重ねて
  いちばんぼやけなかったのが重心だったから（外接矩形の中心 39% → 重心 31%）。

出力の枠は「重心からどこまで伸びるか」を測って決めた
（Dr.よこぼ 300x224 / ニャビット 310x274）。顔は枠の9割ほどを占める。

どのコマを使うかは `node tools/char_index.mjs`。本番と同じ切り出し方で20コマを並べ、
番号（コマの下の棒の数−1）を振った見本を `work/qa-chars/index_*.png` に出す。
実行すると `13=b#3` のような対応表も出るので、その `b#3` を `make_chars.mjs` の
`FACES`（sheet と cell）に書く。

### なぞる画面の相棒

| 顔 | 出るとき |
|---|---|
| 星目 | ★★★（かんぺき） |
| わらい | ★★／★ |
| ？ | はんたいむき・せんのうえを・かたちがちがう |
| あせ | はじめの●から・さいごまで |
| ハート目 | ホネが出た |

**文字のほめ札は消していない。**読める子・大人には文字のほうが速い。顔は足しただけ。

### しょうじょう（ずかん コンプリート）

ホネ30こが そろうと、**ずかんの先頭**に「しょうじょうを みる」が出る。押すと専用画面。
そろえた日は絵の空欄（元画1536x1024の 39.2% / 50.6% / 60.2%）に書きこんでいる。
日付は `dig.certDay` に1回だけ刻む（あとから見ても同じ日が出る）。

**押すと絵ごと90度回して大きく出す。**3:2の絵をたての画面に置くと 366px にしかならず、
「きみは さいこうの はっくつたいだ！」が読めない。回すと 561px（1.5倍）。
端末をよこ向きにすると `orientation:landscape` で回転をやめるので、
首をかたむけても端末を回しても正しく見える。

## 読み上げの声（2026-09-01）

**VOICEVOX:春歌ナナ（ノーマル・styleId 54）。**CM動画作成パイプライン（20260702）で
**ニャビットに使っている声と同じ**＝ラボの中でキャラの声がそろう。
速さは 1.05 倍（CMは1.2倍だが、こちらは字を教える場面）。

焼いたのは**アプリが実際にしゃべる文そのまま**（225本）。台本は書いていない —
`words.js` の `readingOf()` と `bones.js` の `foundText()` から取る。

| 中身 | 本数 |
|---|---|
| 字の読み「あ、ありの あ」（50音表から出るぜんぶ） | 163 |
| ほめことば／やりなおしの理由 | 9 |
| ホネの獲得（恐竜6×部位5） | 30 |
| 全身完成・セット完了・コンプリート | 8 |
| **計** | **210**（6分8秒） |

**ほめことばとやりなおしの理由も声にした。**それまで字で出しているだけで、
まだ字が読めない子には届いていなかった。

- 字を出したとき → 「あ、ありの あ」
- 書けたとき → 「かんぺき！」（字の読みは重ねない。2回続くとくどい）
- ちがう線 → 「せんの うえを なぞろう」

```bash
node tools/build_voice.mjs
```

VOICEVOXエンジンを先に起こす（`%LOCALAPPDATA%/Programs/VOICEVOX/vv-engine/run.exe
--host 127.0.0.1 --port 50021`）。出力は `app/assets/voice.opus`（全部つないだ1本）と
`voice.json`（どこに何があるか）。**`<audio>` を200個持つと iOS で重い**ので、
1つのバッファをデコードして region 再生している（`app/js/audio.js` の `speak(id)`）。
**焼かれていない文は端末の合成音声に落ちる。**

クレジット `VOICEVOX:春歌ナナ` を画面下に常設（背の低い画面でも消さない）。

### 焼くときに引っかかった3つ

- **「ン」の読みが「ん」だけだと、VOICEVOXは音の無いWAVを返す。**長さは普通に返ってくるので
  聞くまで気づけない。`words.js` の `say` を「ん、ラーメンの ん」に直した。
  **焼いたあと波形の山を見て、0.02未満のものを報告する**ようにしてある（`voice.json` の
  `silent` に残り、検査が見る）
- **ことばの無い字（を・づ・ぢ・ゔ）だけ小さく、そして短い。**山の高さが 0.06〜0.10 で、
  ことばつきの 0.34 に対して1/5だった。**焼く前に大きさをそろえる**（上げすぎないよう8倍まで）。
  長さも1拍しかなく 0.26秒で終わるので、**短い文だけ 0.85倍にゆっくり**した
- **フォルダ名が日本語だと ffmpeg の concat がリストを読めない。**ASCIIだけの作業場に
  写してから繋いでいる

### 形式を2つ出している

| ファイル | 大きさ | いつ使うか |
|---|---|---|
| `voice.opus` | 835KB | ふだん。**先取りキャッシュに入る** |
| `voice.m4a` | 1785KB | Opusが `decodeAudioData` で読めない端末（古い iOS Safari）。**先取りしない** |

同じ中身を2つ配るのではなく、**読めた方だけを落とす**。m4a を先取りから外してあるので、
ほとんどの端末は 835KB しか落とさない。

## オフライン（電波が無くても開ける）

`app/sw.js` が一式（2.9MB）を先に取っておく。**電波を切って開き直しても動く。**

- **キャッシュする一覧は自動生成。**手で書くと必ず腐る → `node tools/build_sw.mjs`
- **版は中身のハッシュ**。1バイトでも変われば版が変わり、次に開いたときに入れかわる
- テキストは**改行をそろえてから**ハッシュする。Windowsで作るとCRLF・CIはLFで、
  そろえないと同じ中身でも版が食い違う（実際にCIで捕まえた）
- **ホーム画面アイコンは先取りしない。**ページからは使わず（OSが別に取りに行く）、
  ニャビットの顔にしてから4枚で276KB＝一式の1割をオフライン用に持つ意味がない
- 検査に「sw.jsが最新か」「配信サイズが3.2MBを超えていないか」「電波を切っても開けるか」

## きょうりゅうの きろく

恐竜の詳細ページのいちばん下に、**その恐竜を掘り出した日**と、**そのとき書いた文字**が出る。
筆跡が残っていれば、その子が書いた線そのもの。

- **かんせいび** = 5本目のホネを掘った日
- **はっけんした もじ** = 5本ぶんの文字（重複を除く。最大25字）
- もとは「これから ここに ふやせるよ」という空箱だった。**データはすでに `dig.log` にあった**

パーツのマスを押すと出る記録（1本ぶん）の、恐竜まるごと版。

## れんしゅうを とちゅうでやめたとき

**「もどる」でやめない。とめておく。**ホームのボタンが「つづきから（3もじめの とちゅうから）」
に変わり、同じ場所から再開できる。下に「さいしょから やりなおす」も出る。

5さいの誤タップで、3回×何文字ぶんかの練習がまるごと消えていた。
確認ダイアログではなく、**消えないようにする**方で直した。
（ページを閉じるまでは残る。表から字を選んだ通常練習は、いままでどおり その場かぎり）

## 判定のしかた（お手本との似ぐあい）

**書いた線はそのまま残る。**指が通った道をそのまま描いて、合格したらその線が字になる。
完成した字は「子どもが書いた線」でできていて、お手本の形をなぞり返したものではない。

判定は書き終わってから、**お手本との距離**で採点する。

| 見るもの | 中身 |
|---|---|
| かたち (45%) | お手本の各点から、自分の線までの距離の**平均** |
| きれいさ (35%) | 自分の各点から、お手本までの距離の**平均**（はみ出した分だけ下がる） |
| むき (20%) | 書きはじめ・書きおわりが お手本と合っているか |

平均のズレが `D0`（既定8）に達するとその項目は0点。109の字の中で平均8ずれる＝
画面で25pxくらいで、かなりガタガタな線。

点数 → ★の数は **85点以上=★★★ / 70点以上=★★ / それ未満=★**。
実測（`node tools/verify.mjs` が毎回出す）:

```
ふるえ± 0 → 100点 ★★★   手本からの平均ズレ 0.0
ふるえ± 4 →  88点 ★★★   手本からの平均ズレ 1.2
ふるえ± 8 →  77点 ★★☆   手本からの平均ズレ 2.3
ふるえ±12 →  67点 ★☆☆   手本からの平均ズレ 3.1
ふるえ±16 →  58点 ★☆☆   手本からの平均ズレ 3.8
```

**合格ライン自体はゆるい。**上の5つは全部合格する。★の数で上手さを見せて、
やりなおしになるのは「これは別の線」というときだけ:

| 理由 | 出る言葉 | 条件 |
|---|---|---|
| `reverse` | はんたいから かいてるよ | はじめと終わりが お手本と逆 |
| `off` | せんの うえを なぞろう | 自分の点の55%以上が お手本から16以上離れた |
| `start` | はじめの ●から なぞろう | 書きはじめに17以内で近づいていない |
| `short` | さいごまで なぞろう | 書きおわりに届いていない／途中がごっそり抜けた |

やりなおしのとき、**書いた線は薄い赤で0.5秒残ってから消える**。
何を書いたのかを見せないと、どこが違ったのか分からないため。
ただのタップ（線の長さが6未満）は黙って捨てる。怒られない。

書き順は「今なぞる画」を1画ずつ進めることで守らせる。2画目を先に書いても
今の画として採点されて落ちる。

### かたちを見ているか（5さいの指摘で入れた）

**「す」を「ナ」のように書いても通っていた。**2画目のループを、まっすぐ縦に引くだけ。
「じょうず」まで出ていた。

原因は、かたちの物差しが2つとも**「いちばん近い点」までの距離**だったこと。順番も対応も
見ていないので、**ループのある画は真ん中を横切るだけで全部の点の近くを通れる**。
全画を総当たりで調べたら、約500本のうち**353本**が「始点から終点までまっすぐ」で通った。

直しかた: **長さで等分して「進みぐあいが同じ点」どうしを比べる**（`meanFlow`）。
ループのある画をまっすぐ横切ると、対応する点から大きく離れるので止まる。

しきい値は好みでなく実測で10にした。

| しきい値 | 正しい形を落とす（±16） | まっすぐを止める |
|---|---|---|
| 8 | 3% | 28% |
| 9 | 0.6% | 27% |
| **10** | **0%** | **27%** |

8まで下げても止められる率は1ポイントしか増えないのに、正しい形を落としはじめる。

**まだ339本は まっすぐで通る**が、これは正しい。もともと直線に近い画では、
まっすぐ引くこと自体が正解だから。残っている中でいちばん形が違うのは `に` の2画目（9.8）。

### つまみ（`app/js/tracer.js` の先頭）

| 定数 | 既定 | 意味 |
|---|---|---|
| `D0` | 8 | 点数の物差し。**大きいほど点が甘い** |
| `R_STRAY` | 16 | 「線の上」と認める距離（`off` の判定に効く） |
| `R_END` | 17 | 書きはじめ・書きおわりに「届いた」と認める距離 |
| `R_COVER` | 13 | 「なぞられた」と認める距離（途中抜けの判定） |
| `PASS` | — | やりなおしにする境目。ここを下げるともっとゆるくなる |

「もっとゆるく」なら `D0` を大きく、`PASS` を下げる。「もっとちゃんと」なら逆。

## スマホでの動き

配って遊んでもらう前提なので、指で触ることを先に測っている。

- **入力はPointer Events**。指・ペン・マウスを同じ道で扱う。`touch-action:none` と
  `touchstart` の `preventDefault` で、なぞり中にページが動かないようにしてある
- **2本目の指と手のひらは無視する。**書きかけの線が乗っ取られると「書いたのに消えた」に
  なって、子どもには理由が分からない
- **`pointercancel` は採点しない。**着信やシステムのジェスチャで取り上げられただけなので、
  やりなおしの注意も出さない
- 指の的はぜんぶ44px以上。二本指ズーム・ダブルタップ拡大・引っぱって更新は塞いである
- 画面下の安全域（`env(safe-area-inset-bottom)`）を見てボタンを浮かせている
- **よこ向きのときはボタンを右の列へ逃がす**。たてに積んだままだと書くマスが潰れる
  （844x390で 243px → 312px）
- 最初のタップで AudioContext を起こす（iOSは無音のままになるため）
- `manifest.webmanifest` とアイコンを置いてあるので、**ホーム画面に置くとフルスクリーンで開く**

### スマホ検査

```bash
node tools/verify_mobile.mjs
```

`verify.mjs` はマウスで動かしている。こちらは **CDPの本物のタッチイベント**で指を動かし、
5つの画面サイズ（iPhone SE / iPhone 14 / Android / iPad / よこむき）で70項目を測る。
絵は `work/qa-mobile/` に出る。

測っているのは: 横にはみ出さないか / ページ自体がスクロールしないか / 指の的が44px以上か /
書くマスがボタンやヘッダと重ならないか / **指で実際に字が書けるか**（`pointerType` が
`touch` であることも見る）/ **手のひらが触れても1画目が通るか** / 回しても崩れないか /
ホーム画面に置けるか（マニフェストとアイコンが200で返るか）。

アイコンは `node tools/make_icons.mjs` で作る（SVGをヘッドレスChromeでPNGに焼くだけ。
画像ツールを入れなくていい）。

## 検査

```bash
node tools/verify.mjs
```

ヘッドレスChromeがマウスで実際に字を書いて、94項目を測る（セットを丸ごと走らせるので時間はかかる）。
画面の絵は `work/qa/` に出る（画面が出ない環境でも詰められる）。

**ふるえは線に対して直角に入れる。**線に沿ってずらしても お手本から離れないので、
「±16でなぞった」と書いてあるのに実際は2しか離れていない、という測り方になってしまう。

測っているのは:

- 下手さと点数の対応表（上に載せたもの）。**下手になるほど点が下がるか**、
  **上手・下手で30点以上ひらくか**、★3がていねいなときだけか
- やりなおしの4つの理由が それぞれ正しく出るか（逆向き／はみ出し／途中から／途中まで）
- 残っているのが**指の道**か（お手本の形のコピーでないことを距離で確かめる）
- ただのタップが無視されるか / やりなおしのあと書き直せば進むか
- カタカナ（「ー」を含む）を最後まで書けるか
- ずかんがふせてあるか、なぞると開くか、行がそろうとごほうびが出るか、★が出るか
- **セットを1つ走りきると ホネが1個か**（3回×5文字＝15回なぞる）／通常練習では増えないか
- **通常練習と発掘練習の両方で「つぎ」を隠し、3回成功後に自動で進むか**
- **ダブりが出ないか・あたまが必ず最後か**・30個で6体そろうか
  （なぞりを何百回もやらずに、ルールだけ直接まわして測る）
- **へたに書いてもホネはもらえるか**（点数が報酬にひびかないことの固定）
- ずかんの3状態（そろった／途中／手つかず）で、名前と姿の出しかたが正しいか
- 設定は小さく、スタートと行き来ボタンは画面幅いっぱいか
- **いろんな恐竜が同時に進むか**（はじめの10個が3体以上にまたがるか）
- **ホネの札が出ても書くマスが動かないか**（動くと指の下でマスがずれる）
- **仮の骨が描画枠からはみ出していないか**（はみ出すと黙って切り取られる）
- 178字ぶんのデータと、表の字のことば・形がそろっているか
- **ヘッダのボタンが横に伸びていないか**（CSSのクラス名衝突は静かに壊れる）


**本番URLに対しても そのまま走る。**

```bash
NAZORIN_URL=https://yokobo103.github.io/nazotte_dinosaur/ node tools/verify.mjs
```

中で読み込むモジュールを相対パスにしてある（`./data/kana.js`）。
絶対パスだとサブパス配信で404になり、**本番だけ検査できない**状態になる。
